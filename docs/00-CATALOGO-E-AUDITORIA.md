### Nota (f) — `boraoztunc/skills` é agregador, e isso muda a licença

A API do GitHub reporta `Apache-2.0` para esse repositório, mas **isso está errado na prática**. Não existe `LICENSE` na raiz: existem três arquivos separados (`LICENSE-hyperframes`, `LICENSE-mengto-skills`, `LICENSE-liamgvchi`) mais NOTICEs de atribuição. O repositório é um agregador — cada conjunto de skills carrega a licença do upstream real, e o conteúdo próprio do autor é MIT.

As 6 skills que vieram de lá receberam a licença correta, com a procedência no cabeçalho do `LICENSE.txt`:

| Skill | Upstream real | Licença |
|---|---|---|
| [[apple-design]] | [emilkowalski/skills](https://github.com/emilkowalski/skills) | MIT — © 2026 Emil Kowalski |
| [[ogilvy-copywriting]] | conteúdo próprio do `boraoztunc` | MIT |
| [[make-interfaces-feel-better]] | conteúdo próprio do `boraoztunc` | MIT |
| [[animejs]] · [[css-animations]] · [[lottie]] | [heygen-com/hyperframes](https://github.com/heygen-com/hyperframes) | Apache-2.0 |

**Duas ressalvas de curadoria descobertas na conferência final:**

1. **`animejs`, `css-animations` e `lottie` são adaptadores do HyperFrames**, a ferramenta de vídeo da HeyGen — não são skills genéricas de animação web. Só valem se você usar HyperFrames. Para animação de site, o par certo é [[animation-systems]] + [[gsap]].
2. **[[make-interfaces-feel-better]] é uma versão anterior de [[better-ui]]**, do `jakubkrehel`. O `SKILL.md` do `better-ui` tem 9,8 KB contra 6,2 KB, e traz `icons.md` que o outro não tem. Os arquivos homônimos (`animations.md`, `surfaces.md`, `performance.md`) têm hash diferente — é fork antigo, não cópia. **Prefira [[better-ui]]**; `make-interfaces-feel-better` só sobrevive porque tem `typography.md`, que virou [[better-typography]] no upstream.

## 3. Duas coisas que você deve saber

### 3.1 — Por que o `caveman` (95.500 ⭐) ficou de fora

Baixei e li o código antes de decidir. O repositório é **honesto**: tem `SECURITY.md` explicando cada comportamento que dispara alerta em scanner, o `subprocess.run()` usa lista fixa de argumentos (sem `shell=True`, sem interpolação de string), há um `SENSITIVE_BASENAME_REGEX` que recusa comprimir arquivos como `credentials.md` ou `secrets.txt`, e existe limite de 500KB antes de qualquer chamada de API. Não achei nada malicioso.

Rejeitei por **adequação**, não por segurança:

1. **A skill principal `caveman` faz o Claude responder em inglês quebrado de caverna** ("why use many token when few token do trick"). Reduz ~65% do output — e destrói a legibilidade das respostas em português que você usa no dia a dia.
2. **`caveman-compress` gasta token para economizar token.** Ele lê seu arquivo de memória, **manda para a API da Anthropic** e reescreve o arquivo comprimido no lugar. Seu `MEMORY.md` tem 3 linhas. O custo da chamada é maior que a economia.
3. Ele **reescreve seus arquivos de configuração no lugar** (com backup fora da árvore). Risco desnecessário para ganho zero no seu caso.

O que as skills de [[_10-eficiencia-de-contexto]] fazem no lugar: em vez de encolher o texto **depois** que ele já entrou na janela, elas impedem o texto de entrar — mascarando saída verbosa de ferramenta ([[context-optimization]]), jogando volume para disco ([[filesystem-context]]) e delegando exploração a subagente cujo contexto nunca volta pro principal ([[dispatching-parallel-agents]]). É economia estrutural, não cosmética.
